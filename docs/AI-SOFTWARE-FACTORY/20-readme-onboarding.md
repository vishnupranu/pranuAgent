# 20 — README and Developer Onboarding

The root README must be kept aligned with actual verified behavior. It must include:

1. Product description and supported platforms.
2. Current feature status with implemented vs planned clearly separated.
3. Architecture links and specification index.
4. Prerequisites and verified version ranges.
5. Windows PowerShell setup instructions.
6. Intel macOS setup instructions.
7. Local Ollama configuration and model selection.
8. Local development and test commands taken from package scripts.
9. Build and desktop packaging commands only once implemented and tested.
10. Environment variables with placeholders and secret-handling warnings.
11. Project folder/storage location.
12. Security model, sandbox limitations and approval behavior.
13. Troubleshooting: Ollama unavailable, model missing, port in use, dependency install/build failure, preview crash.
14. Git workflow, contribution guidance and branch protection.
15. Deployment instructions for Vercel, optional self-hosting and custom domain.
16. Open-source notices and license information.
17. Known limitations and a roadmap.
18. Backup, export, restore and uninstall instructions.

A clean-machine onboarding test must follow the README without relying on undocumented steps or credentials belonging to the author.
